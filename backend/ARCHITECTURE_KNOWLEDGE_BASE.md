## 📊 数据流程

### 1. 文件上传流程

```
用户上传文件
    │
    ▼
FastAPI 接收文件
    │
    ├─► 保存到 MinIO (原始文件)
    │
    ├─► 创建数据库记录 (status: pending)
    │
    └─► 提交 Celery 任务
            │
            ▼
    Celery Worker 处理
            │
            ├─► 从 MinIO 下载文件
            │
            ├─► OCR 提取文本 (如果是 PDF)
            │   └─► PaddleOCR API
            │
            ├─► 插入 LightRAG
            │   ├─► 文本分块
            │   ├─► 实体提取
            │   ├─► 关系抽取
            │   ├─► 向量化 (Qwen Embedding)
            │   └─► 存储到 Neo4j
            │
            └─► 更新数据库状态 (completed/failed)
```

### 2. 查询流程

```
用户提交查询
    │
    ▼
FastAPI 接收查询
    │
    ▼
LightRAG Service
    │
    ├─► 查询向量化 (Qwen Embedding)
    │
    ├─► 检索相关内容
    │   ├─► 向量相似度搜索
    │   └─► 知识图谱查询 (Neo4j)
    │
    ├─► 生成答案 (LLM)
    │   └─► OpenAI 兼容 API
    │
    └─► 返回结果
```

## 🗄️ 数据模型

### 数据库表结构

```sql
-- 知识库表
knowledge_bases
├── id (PK)
├── name
├── description
├── status (active/inactive/processing)
├── working_dir (LightRAG 工作目录)
├── owner_id (FK -> users.id)
├── created_at
└── updated_at

-- 文件表
knowledge_files
├── id (PK)
├── filename
├── original_filename
├── file_size
├── file_type (pdf/txt/md)
├── minio_path (MinIO 存储路径)
├── status (pending/processing/completed/failed)
├── error_message
├── task_id (Celery 任务 ID)
├── knowledge_base_id (FK -> knowledge_bases.id)
├── uploaded_by (FK -> users.id)
├── created_at
└── processed_at
```

### Neo4j 图谱结构

```
(Entity) -[Relationship]-> (Entity)
    │
    ├─► 实体节点
    │   ├── name: 实体名称
    │   ├── type: 实体类型
    │   └── description: 实体描述
    │
    └─► 关系边
        ├── type: 关系类型
        ├── description: 关系描述
        └── weight: 关系权重
```

## 🔧 技术组件

### 1. Web 层
- **FastAPI**: REST API 框架
- **Pydantic**: 数据验证
- **JWT**: 用户认证

### 2. 服务层
- **KnowledgeBaseService**: 业务逻辑
- **MinIOService**: 对象存储
- **LightRAGService**: 知识图谱
- **OCRService**: 文档处理

### 3. 存储层
- **SQLite**: 元数据存储
- **MinIO**: 文件对象存储
- **Neo4j**: 知识图谱存储
- **Redis**: 消息队列

### 4. 处理层
- **Celery**: 异步任务队列
- **PaddleOCR**: OCR 文本提取
- **LightRAG**: 知识图谱构建

### 5. AI 层
- **Qwen Embedding**: 文本向量化
- **OpenAI API**: LLM 推理

## 🔐 安全设计

### 认证授权
```
用户请求
    │
    ▼
JWT Token 验证
    │
    ├─► 有效 → 提取 user_id
    │
    └─► 无效 → 401 Unauthorized
            │
            ▼
    权限检查 (owner_id == user_id)
            │
            ├─► 通过 → 执行操作
            │
            └─► 拒绝 → 403 Forbidden
```

### 数据隔离
- 每个用户只能访问自己的知识库
- 文件路径包含 user_id 和 kb_id
- 数据库查询自动过滤 owner_id

## 📈 性能优化

### 1. 缓存策略
- **LightRAG 实例缓存**: 避免重复初始化
- **Redis 缓存**: 查询结果缓存（可选）

### 2. 异步处理
- **文件上传**: 立即返回，后台处理
- **Celery 队列**: 支持并发处理

### 3. 资源管理
- **连接池**: 数据库连接复用
- **文件流**: 大文件流式处理
- **临时文件**: 自动清理

## 🎯 设计原则

1. **关注点分离**: API、服务、存储分层
2. **依赖注入**: 便于测试和替换
3. **异步优先**: 避免阻塞操作
4. **错误处理**: 完善的异常捕获
5. **可观测性**: 日志、监控、追踪
6. **可扩展性**: 支持水平扩展
